# Operations

The Admin Panel reads host CPU, RAM, swap, and disk from a configured Sanaei panel's authenticated `server/status` API. It reads attached node CPU, RAM, uptime, and reported online count from `nodes/list` on demand. This is a normal API integration, not an AI agent and not a process installed on each node. Node swap and disk are not available from that endpoint. If an API call fails or a host sample is older than five minutes, the dashboard shows unavailable/stale rather than making up a value. Verify these readings against the Sanaei UI after each panel is connected.

- `docker compose ps` and `docker compose logs --tail=100 api worker caddy db` show service health.
- `curl https://DOMAIN/api/health` verifies the API and database.
- `/status` and `/alerts` in the bot work only for the configured Telegram admin ID.
- The panel shows latest server metrics, open alerts, and retrying or failed jobs. An unavailable metric indicates no valid sample, never a fabricated value.
- Jobs retry with exponential backoff for up to five attempts. Before retrying a failed job manually, inspect its remote idempotency key and the target service state.
- `./backup.sh` writes AES-GCM encrypted database, configuration, source, and private receipt archives under `backups/`. `schedule-backups.sh` installs an hourly cron job and retains 14 versions. Copy all four encrypted archives off the VPS and save `BACKUP_ENCRYPTION_KEY` separately. Check `backups/backup.log` and test a restore on an isolated host. `./restore.sh backups/TIMESTAMP.dump.enc` decrypts and verifies a database dump before replacing the current database after explicit confirmation. Restore the matching configuration, source, and private receipt archives separately first, using the same backup key. Private receipts are in Docker volume `private_data`; no automated in-place private-volume restore is provided.
- Database migrations run at process startup with a PostgreSQL advisory lock. `./update.sh release.tar.gz` backs up before applying a validated release archive and checks HTTPS health. Application and migration rollback remain manual; some migrations may not be reversible. Running `./update.sh` without an archive assumes source was already staged, so its source snapshot contains that staged release rather than the previous one.

Expiration calls the target provider's disable endpoint before changing database state. A failed disable attempt keeps the subscription active in the database and creates an alert for operator attention.

The Sanaei worker also checks traffic exhaustion and disables consumed clients. Terminal wallet-funded provisioning failures create an idempotent wallet refund. Stars, NOWPayments, and manual refunds require operator handling; do not mark them refunded before a real refund is confirmed. Preserve `PANEL_ENCRYPTION_KEY` with your restore plan. See [INTEGRATIONS.md](INTEGRATIONS.md) for the live verification checklist.

Renewal jobs reuse the original subscription and panel client. Their prepared target is durable across retries. If a renewal reaches terminal failure, inspect the panel's actual expiry and traffic limit before approving its refund request: the provider may have applied an update before a timeout. Refund-only review never disables the existing client. The admin renewal history includes unpaid checkout attempts as well as jobs. Apply migration `014` during the normal release update; keep all earlier migrations and persistent volumes.

Operational events use the `ops_events` queue. When `OPS_CHAT_ID` and matching `OPS_TOPIC_*` values are set, the worker sends fixed labels and numeric IDs to private Telegram topics with retry. Topic delivery may duplicate a message after a send succeeds but before database confirmation. `GET /api/admin/finance/report` and the Admin Panel Finance section show business entries separately from wallets; manual sales there do not provision a service. Exports over 10,000 rows require a narrower date range.
